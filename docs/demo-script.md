# 3–4 分钟面试演示脚本

## 0:00–0:35 问题与转向

“这个项目最初想做快速报价，但继续拆工作流后发现，熟练老板并不缺计算器。真正昂贵的是双方默认理解不同：客户说‘正规’，老板做成黑体，客户心里想的是宋体。于是产品从快速报价转向需求对齐。”

## 0:35–1:20 识别歧义

选择“标准门头询价”，点击“识别需要确认的地方”。指出：

- 左栏保留原始证据；“三米左右”“正规大气”“下周五前”以歧义色标出。
- 明确要求和模糊描述分开；系统明确列出不允许偷偷采用的假设。
- 中栏按返工风险和价格影响排列问题，并在问题中引用客户原话。
- 页面右上角明确显示当前是 DeepSeek Agent 还是本地演示；无 Key 或模型失败会降级，不伪装成真实调用。

切换到“明确字体”案例，说明客户已经说“黑体”时，系统只要求确认该明确值，不再重复询问字体类型。

## 1:20–2:10 逐项确认

返回标准案例，展示字体的“稳重正式 / 简洁现代 / 传统文化”选项，而不是只堆专业术语。完成两三个选择，右侧确认单实时变化。为控制演示时间，点击“应用预设确认（演示）”。

也可输入一个预设之外的自定义回答：它会回到 `/api/refine`，由 Agent 结合当前需求状态判断是否足以确认；仍然模糊时继续追问，足够时再自动进入下一题。

强调正式报价按钮此前被锁住；确认齐全后才解锁。前端状态之外，后端还会独立校验必需字段。

## 2:10–3:00 确定性报价与验收

点击“生成确定性报价”：

- 逐项展示规格、数量、小计和计价规则。
- 所有单价都来自 YAML 的演示门店内部价目；模型不心算价格。
- 展开假设和不包含项目，指出真实项目仍需人工复核。
- 展示可检查的尺寸、外观、发光和现场清理验收标准。

## 3:00–3:35 变更与交付

回到任一已确认字段改选另一个值，展示“需求变更”记录和报价失效后重新计算。复制微信确认话术，最后说明可浏览器打印确认单。

## 3:35–4:00 FDE 总结

“这不是拿一个固定 AI 产品寻找场景，而是先进入门店从询价到施工的真实信息流，找到信息丢失、理解偏差和责任模糊的节点，再用最小闭环验证：客户是否愿意确认、门店是否减少返工。当前演示不声称已经验证商业效果。”
