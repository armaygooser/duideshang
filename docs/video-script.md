# 90 秒演示录屏台本

建议使用 16:9、1080p、30fps 录制。提前清空会话并选择“标准门头询价”，不要在视频中展示开发者工具、环境变量或 API Key。

## 0–8 秒：问题与产品

画面：展示工作台完整首页。

> 大家好，这是“对得上”，一个面向小微广告制作门店的需求澄清与透明报价助手。它解决的核心问题不是老板不会算价格，而是客户表达模糊，双方理解不一致，最终导致返工和客诉。

## 8–20 秒：客户原话

画面：展示标准案例的客户原话，点击“识别需要确认的地方”。

> 比如客户说：想做一个三米左右的门头，正规大气一点，要能发光，预算四千，下周五前弄好。老板虽然可以很快估价，但“三米左右”“正规大气”“能发光”都不能直接用于生产。

## 20–35 秒：识别歧义

画面：指向左侧证据标记和中间的待确认问题。

> 系统首先保留客户原话作为证据，再区分明确表达、存在歧义和缺失信息。它不会擅自把“正规”理解成某一种字体，也不会把“三米左右”直接写成生产尺寸。

## 35–58 秒：逐项确认

画面：手动确认两到三个高风险问题，然后使用预设完成其余项目。

> Agent 会按照对价格和交付的影响排序追问。例如，它会询问客户想要黑体、宋体还是其他视觉风格；发光效果是正面发光、背面发光还是轮廓发光。客户每确认一项，右侧需求确认单会同步更新，并保留确认记录。

## 58–75 秒：透明报价

画面：确认进度达到 100%，生成报价并停留在价格组成区域。

> 当高风险需求确认完成后，系统才允许生成报价。报价不是只给一个总数，而是展示材料、尺寸、运输等价格组成，同时明确计价假设和不包含项目，让客户理解价格是如何形成的。

## 75–85 秒：验收标准

画面：指向报价单下方的验收标准。

> 系统还把需求转化为可检查的验收标准，例如尺寸误差、字体排版、安装牢固和现场清理。这让双方不仅对得上价格，也能对得上最终交付结果。

## 85–95 秒：总结

画面：回到完整三栏工作台。

> 这个项目中，AI 负责理解口语、发现歧义和组织追问；价格计算、报价门槛和验收规则由确定性程序控制。它展示的是我作为 FDE 进入真实工作流、重新定义问题，并把 AI、业务规则和人工确认组合成可交付闭环的能力。谢谢。
